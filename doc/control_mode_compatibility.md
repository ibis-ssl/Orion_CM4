# 制御モードの機体別互換性

crane→CM4の制御指令は、先頭`CHECK_COUNTER` 1バイトと64バイトの指令本体で構成する。指令本体のbyte 23が`CONTROL_MODE`である。Orion（4輪オムニ、G474搭載）と4WS（4輪駆動・4輪操舵）でこの外枠を共用し、CM4が搭載Mainに応じて下流の指令へ変換する。

| mode | 指令の意味 | Orion | 4WS | CM4から下流への経路 |
|---|---|---|---|---|
| `3` | 極座標の速度目標 | 対応 | 対応予定 | OrionではG474へ直接送信できる。4WSではCM4がSPIの機体速度指令へ変換する。 |
| `4` | 位置目標と到達時速度 | 対応 | 対応予定 | CM4で位置制御し、機体に応じてmode 3・5・6のいずれかへ変換する。mode 4をG474へ直接送らない。 |
| `5` | 各輪の駆動周速度と操舵角 | 非対応 | 対応予定 | CM4が4WS Main向けSPIの4モジュール目標へ変換する。 |
| `6` | 各輪の駆動周速度 | 対応予定 | 非対応 | Orion専用。G474でのmode 6受信はFW拡張が必要。 |

mode 4から選べる出力は、Orionではmode 3または6、4WSではmode 3または5に限る。選択規則と、各モード間の座標・方位変換は制御分担を決めてから確定する。対応しない機体向けのmode 5・6を別のモードとして解釈せず、指令を拒否して安全停止する。

現在のOrion_CM4とG474で動作するのはmode 3・4を使い、CM4がmode 4をmode 3へ変換する経路である。mode 5・6、および4WS上でのmode 3・4は仕様案で、まだ実装されていない。G474へ直接送れるのはmode 3であり、mode 6を使うにはG474側のパケット復号と車輪制御も拡張する。

## Orion専用mode 6の配置案

指令本体byte 0..23はmode 3・4・5と共通とし、byte 23に`OMNI_WHEEL_SPEED_TARGET_MODE = 6`を入れる。mode 6はmode 5の4輪目標から操舵角を除き、駆動周速度だけを詰めた形式とする。

| 指令本体のbyte | 内容 |
|---|---|
| 24..25 | 車輪0の駆動周速度 [m/s] |
| 26..27 | 車輪1の駆動周速度 [m/s] |
| 28..29 | 車輪2の駆動周速度 [m/s] |
| 30..31 | 車輪3の駆動周速度 [m/s] |
| 32..63 | mode 6では予約、0 |

各速度は[4WSのmode 5](4ws_spi_packet_proposal.md)と同じ2バイト符号化を使用する。符号化範囲は±32.767 m/sで、上位バイト、下位バイトの順に格納する。`0x7FFF`は0、`0xFFFF`は無効値とする。機構上の速度上限、車輪番号と配置、正回転方向は別途定義する。`STOP_EMERGENCY`は車輪目標より優先する。

mode 6ではbyte 32..37をmode 4の位置目標として復号しない。送信側とCM4側にはmode 6専用のシリアライザとデシリアライザが必要である。既存の汎用シリアライザはbyte 32..37に位置関連値を書き込むため、mode番号だけを増やして使用しない。

mode 5の配置と4WS向けSPIフレームは[4WS MainとのSPI通信案](4ws_spi_packet_proposal.md)、実装済みのmode 3・4とG474向けUARTの詳細は[制御パケット](control_packet.md)を参照する。
