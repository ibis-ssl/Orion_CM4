# 制御モードの機体別互換性

crane→CM4の制御指令は、先頭`CHECK_COUNTER` 1バイトと64バイトの指令本体で構成する。指令本体のbyte 23が`CONTROL_MODE`である。Orion（4輪オムニ、G474搭載）と4WS（4輪駆動・4輪操舵）でこの外枠を共用し、CM4が搭載Mainに応じて下流の指令へ変換する。

| mode | 指令の意味 | Orion | 4WS | CM4から下流への経路 |
|---|---|---|---|---|
| `3` | 極座標の速度目標 | 対応 | 対応予定 | OrionではG474へ直接送信できる。4WSではCM4がSPIの機体速度指令へ変換する。 |
| `4` | 位置目標と到達時速度 | 対応 | 対応予定 | CM4で位置制御し、機体に応じてmode 3・5・6のいずれかへ変換する。mode 4をG474へ直接送らない。 |
| `5` | 各輪の駆動周速度と操舵角 | 非対応 | 対応予定 | CM4が4WS Main向けSPIの4モジュール目標へ変換する。 |
| `6` | 各輪の駆動周速度 | 対応予定 | 非対応 | Orion専用。G474でのmode 6受信はFW拡張が必要。 |
| `7` | ボール基準の相対速度 | 対応予定 | 対応予定 | CM4がローカルカメラのボール検出を用いて変換する。ボール未検出時はmode 3の速度指令として扱う。 |
| `8` | ボール基準の相対位置 | 対応予定 | 対応予定 | CM4がローカルカメラのボール検出を用いて変換する。ボール未検出時はmode 4の位置指令として扱う。 |

mode 4から選べる出力は、Orionではmode 3または6、4WSではmode 3または5に限る。選択規則と、各モード間の座標・方位変換は制御分担を決めてから確定する。対応しない機体向けのmode 5・6を別のモードとして解釈せず、指令を拒否して安全停止する。

mode 7・8もOrionと4WSの共通モードとする。CM4でボール基準の目標を通常の機体指令へ変換し、mode 7・8の値をG474や4WS Mainへそのまま渡さない。ボールが見えない場合も、mode 7・8の番号を下流に送らず、それぞれmode 3・4と同じ処理へ切り替える。

現在のOrion_CM4とG474で動作するのはmode 3・4を使い、CM4がmode 4をmode 3へ変換する経路である。mode 5～8、および4WS上でのmode 3・4は仕様案で、まだ実装されていない。G474へ直接送れるのはmode 3であり、mode 6を使うにはG474側のパケット復号と車輪制御も拡張する。

## Orion専用mode 6の配置案

指令本体byte 0..23はmode 3・4・5と共通とし、byte 23に`OMNI_WHEEL_SPEED_TARGET_MODE = 6`を入れる。mode 6はmode 5の4輪目標から操舵角を除き、駆動周速度だけを詰めた形式とする。

| 指令本体のbyte | 内容 |
|---|---|
| 24..25 | 車輪0の駆動周速度 [m/s] |
| 26..27 | 車輪1の駆動周速度 [m/s] |
| 28..29 | 車輪2の駆動周速度 [m/s] |
| 30..31 | 車輪3の駆動周速度 [m/s] |
| 32..63 | mode 6では予約、0 |

各速度は[4WSのmode 5](4ws_spi_packet_proposal.md)と同じ2バイト符号化を使用する。符号化範囲は±32.767 m/sで、上位バイト、下位バイトの順に格納する。`0x7FFF`は0、`0xFFFF`は無効値とする。機構上の速度上限、車輪番号と配置、正回転方向は別途定義する。`STOP_EMERGENCY`は車輪目標より優先する。

mode 6ではbyte 32..37をmode 4の位置目標として復号しない。送信側とCM4側にはmode 6専用のシリアライザとデシリアライザが必要である。既存の汎用シリアライザはbyte 32..37に位置関連値を書き込むため、mode番号だけを増やして使用しない。

## ボール基準の共通モード7・8の配置案

mode 7・8も65バイト外枠と指令本体byte 0..23の共通フィールドを使用し、byte 23をそれぞれ`BALL_RELATIVE_VELOCITY_MODE = 7`、`BALL_RELATIVE_POSITION_MODE = 8`とする。ボール基準の並進量と、ボール未検出時に使う通常の目標は別フィールドに入れる。`STOP_EMERGENCY`は検出状態と目標値より優先する。

| 指令本体のbyte | mode 7：ボール基準の相対速度 | mode 8：ボール基準の相対位置 |
|---|---|---|
| 24..25 | 未検出時のmode 3 `target_global_velocity_r` [m/s] | 未検出時のmode 4 `terminal_velocity_x` [m/s] |
| 26..27 | 未検出時のmode 3 `target_global_velocity_theta` [rad] | 未検出時のmode 4 `terminal_velocity_y` [m/s] |
| 28..29 | 検出時のボール基準相対速度 `relative_velocity_x` [m/s] | 検出時のボール基準相対目標位置 `relative_target_x` [m] |
| 30..31 | 検出時のボール基準相対速度 `relative_velocity_y` [m/s] | 検出時のボール基準相対目標位置 `relative_target_y` [m] |
| 32..33 | 予約、0 | 未検出時のmode 4 `TARGET_GLOBAL_POS_X` [m] |
| 34..35 | 予約、0 | 未検出時のmode 4 `TARGET_GLOBAL_POS_Y` [m] |
| 36..37 | 予約、0 | 未検出時のmode 4 `TERMINAL_VELOCITY` [m/s] |
| 38..63 | 予約、0 | 予約、0 |

各2バイト値は[制御パケット](control_packet.md)と同じ上位バイト先行の符号化を使う。位置と並進速度の符号化範囲は±32.767 mまたはm/s、mode 7の未検出時の方向角はmode 3と同じ±32.767 radとする。実際に許す速度・距離は別途制限する。送信側は両方の目標を設定し、受信側は使用する側をカメラの検出状態で選ぶ。共通フィールドの目標方位はグローバル方位のままとし、ボール基準にするのは並進2軸とする案である。

CM4はローカルカメラUDPの最新7バイトからボールの可視性を判定する。候補条件は`radius > 0`かつ最終受信から100 ms以内である。`x`・`y`は画像座標、`radius`は画像上の半径であり、そのままメートル単位の目標と比較しない。ボールが見える場合、CM4がカメラの観測値からボール基準の位置・速度を求め、選択した機体向けのmode 3・5・6相当の指令へ変換する。mode 8の相対目標に到達したときの目標速度は0とする。

ボール未検出またはカメラ更新停止時は、mode 7のbyte 24..27をmode 3指令として扱い、mode 8のbyte 24..27と32..37をmode 4指令として扱う。mode 8ではCM4の位置制御を通した後、Orionならmode 3または6、4WSならmode 3または5へ変換する。検出状態の切り替え時はボール追従側の制御状態をリセットし、保存したボール位置を有効な新規観測として使わない。crane指令や機体feedbackが失効した場合は、カメラが見えていても安全停止を優先する。

カメラが出すのは画像座標と半径であり、ボール基準のメートル座標や速度ではない。実装前にカメラ較正、距離推定、軸の向き、ボール速度の推定方法、検出の信頼度と制御周期を決める。変換が未定義のままmode 7・8を走行指令として採用しない。

mode 5の配置と4WS向けSPIフレームは[4WS MainとのSPI通信案](4ws_spi_packet_proposal.md)、実装済みのmode 3・4とG474向けUARTの詳細は[制御パケット](control_packet.md)を参照する。
